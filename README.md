# Уведомления по просроченной рассрочке — a.ok-crm.com

Парсит заказы на рассрочке (Метод оплаты = Расчетный счет, Банк = Фирма
рассрочка, Статус = Сдан), находит платежи, просроченные больше чем на
7 дней и ещё не оплаченные, и:

1. Пишет их в Google Таблицу, лист **«Уведомления»**.
2. Формирует Excel-файл (только телефоны, в столбик) для робота СМС.

Уже отправленные (пока не оплаченные) платежи не дублируются между
запусками — состояние хранится в `state.sqlite`.

## Установка на новый компьютер

1. Установить **Google Chrome** и **Python** (галочка «Add Python to PATH»).
2. Скопировать всю папку проекта.
3. Скопировать `config.example.txt` → `config.txt`, заполнить
   `GOOGLE_SHEET_WEBHOOK` после настройки Apps Script (см. ниже).
4. Запустить `start.bat` — при первом запуске сам поставит venv и
   библиотеки Playwright.
5. При первом запуске откроется Chrome — войти в CRM через Google вручную,
   дальше сессия сохранится в `chrome_profile\`.

`chrome_profile\`, `state.sqlite`, `venv\` — не переносить между
компьютерами, создаются заново на каждом.

## Настройка Google Таблицы (Code.gs)

1. Создать **новую отдельную** Google Таблицу под этот проект (решили не
   трогать существующий Code.gs, который занят другими задачами). `Code.gs`
   в этом проекте сам создаст лист «Уведомления» при первом запуске, если
   его ещё нет — вручную ничего создавать не нужно.
2. Расширения → Apps Script → вставить содержимое `Code.gs`.
3. Развернуть → Новое развёртывание → Веб-приложение → «Выполнять от
   имени: я», «Доступ: Все» → Развернуть.
4. Скопировать URL веб-приложения в `config.txt`, поле
   `GOOGLE_SHEET_WEBHOOK`.
5. **После любого изменения `Code.gs`** — обязательно новая версия
   развёртывания (Управление развёртываниями → карандаш → Новая версия),
   иначе изменения не подхватятся.

## Проверка селекторов перед первым боевым запуском (ВАЖНО)

Код написан по скриншотам, но CRM не проверялась вживую при разработке.
Перед первым запуском на реальных данных пройти по `selectors.py` и
свериться с сайтом через DevTools (F12):

1. **Параметры фильтра списка заказов** (`FILTER_PARAMS` в selectors.py):
   - Открыть `/order/index`, вручную выставить фильтр (Метод оплаты =
     Расчетный счет, Банк = Фирма рассрочка, Статус = Сдан), нажать
     «Фильтр».
   - Посмотреть на итоговый URL в адресной строке — точные имена
     параметров (`OrderSearch[...]`) скопировать в `FILTER_PARAMS`.
2. **Индексы колонок в списке заказов** (`LIST_COL`):
   - Навести на ячейку ID и ячейку телефона в таблице списка, посмотреть
     порядковый номер `<td>` в DevTools, поправить `LIST_COL["id"]` и
     `LIST_COL["phone"]`.
3. **Параметр пагинации** (`PAGE_PARAM`):
   - Перейти на 2-ю страницу списка вручную, посмотреть что добавилось в
     URL.
4. **Текст кнопки логина** (`GOOGLE_LOGIN_MARKER_TEXT`) — не обязательно
   для работы (используется только `ORDERS_TABLE_LOADED_XPATH`), но можно
   свериться для точности.
5. Запустить `python bot.py` и последить за первыми 5-10 заказами в
   консоли — если что-то не находится, скрипт сохранит скриншот в
   `error_screenshots\` и запись в `errors.csv` с order_id, по которому
   легко открыть тот же заказ в CRM руками и сравнить с XPath в
   `selectors.py`.

## Ключ дедупликации платежа

Сейчас платёж идентифицируется как `order_id + Дата истечения + Сумма`
(`state_db.py`, функция `make_key`). Это надёжно в большинстве случаев,
но если в интерфейсе CRM у кнопки редактирования платежа в колонке
«Действия» есть числовой ID платежа в ссылке (`href`) — лучше
использовать его вместо составного ключа, он будет однозначнее. Стоит
проверить при первом запуске.

## Запуск по расписанию

Через Планировщик заданий Windows: создать задачу, которая запускает
`start.bat` (или напрямую `venv\Scripts\python.exe bot.py`) раз в
день/неделю. Состояние `state.sqlite` между запусками сохраняется, так
что уже отправленные уведомления не задублируются.
